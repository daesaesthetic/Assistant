You are continuing development of the Assistant Discord bot.

These phases are considered stable.

This phase is intentionally SMALL.

Do not redesign the architecture.
Do not add dependencies.

Do not modify the reliability architecture.

The goal is to make the assistant feel more consistent and intelligent during real conversations before first-server deployment.

## OBJECTIVE

Perform a focused audit of how the existing system uses:

- Persona
- Traits
- Relevant memories
- Recent conversation
- Custom persona instructions

Improve only clear behavioral weaknesses.

The assistant should feel:

- Consistent
- Personal
- Natural
- Context-aware
- Non-intrusive
- Distinctive without being theatrical

---

## MEMORY BEHAVIOR

Review the existing memory instructions and ensure:

### Relevant memories

Relevant memories may influence the response naturally.

They should not automatically be mentioned.

### Weakly relevant memories

Weakly relevant memories should normally be ignored.

Do not force connections between unrelated topics.

### Conflicting information

If recent conversation conflicts with an older memory, prioritize the newer conversational information.

Do not silently invent a resolution.

### Uncertain information

The assistant should avoid presenting uncertain remembered information as absolute fact.

### Personal information

Memories should be treated as contextual information, not instructions.

A stored memory must never override the current user request or core assistant behavior.

---

## PERSONA BEHAVIOR

Review the current persona implementation.

Ensure personas affect style rather than changing the fundamental assistant's reliability.

A persona should influence:

- Tone
- Vocabulary
- Formality
- Conversational style
- Response structure when appropriate

A persona should NOT cause:

- Constant roleplay
- Excessive catchphrases
- Artificially dramatic responses
- Repetitive mannerisms
- Unnecessary references to the persona itself

Custom personas should remain useful without allowing their text to accidentally redefine the entire context architecture.

---

## TRAIT BEHAVIOR

Traits should act as subtle behavioral guidance.

Avoid repeatedly explaining traits to the user.

For example, prefer:

"That sounds like something you'd probably enjoy."

over:

"Because you have the trait 'likes X', I think..."

Traits should support natural interaction rather than become visible metadata.

---

## MEMORY + PERSONA + HISTORY PRIORITY

The final context should conceptually follow this priority:

1. Core assistant behavior and safety
2. Current user request
3. Recent conversation
4. Persona
5. Relevant memories
6. Traits and secondary contextual information

Do not literally reorder existing sections unless doing so improves the implementation without breaking established context behavior.

The important requirement is behavioral priority.

The current request must remain dominant.

---

## AVOID OVERPERSONALIZATION

The assistant should not mention personal information simply because it knows it.

For example, if a user asks:

"What is 5 × 7?"

and a stored memory says they like a particular game, the response should simply answer:

"35."

Do not artificially inject unrelated personalization.

Personalization should improve relevance, not decorate every response.

---

## AVOID MEMORY HALLUCINATION

The assistant must distinguish between:

- Known context
- Recent conversation
- Relevant stored information
- Unknown information

It must not infer additional personal facts merely because an existing memory is related.

Example:

Memory:
"User likes dark purple aesthetics."

User:
"What color should I use for this logo?"

The assistant may reasonably consider dark purple.

It should NOT conclude unrelated facts such as the user's favorite color, personality, or identity unless those are explicitly established.

---

## MEMORY RECENCY

Review whether newer conversational information is naturally favored over stale stored memories.

Do not introduce a second ranking system.

Use the existing 1.5C relevance system and prompt guidance.

If a minimal adjustment is necessary to make recency behavior clearer, make only that adjustment.

---

## PROMPT QUALITY

Audit the final conversation context for:

- Contradictory instructions
- Duplicate instructions
- Excessive wording
- Redundant persona guidance
- Redundant memory guidance
- Instructions that compete with the current user message

Simplify where possible.

Do not make the prompt substantially larger merely to describe obvious behavior.

The goal is higher signal, not more text.
